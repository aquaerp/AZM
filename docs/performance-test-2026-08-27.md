# تقرير أداء المرحلة الرابعة — 2026-08-27

## النطاق

- قاعدة PostgreSQL معزولة باسم `azm_loadtest`.
- كل مجموعة تنشئ عبر HTTP API عميلًا ومركبة وبطاقة عمل، مع بقاء سجل التدقيق والصلاحيات والمصادقة فعالة.
- حد القبول: صفر إخفاقات، تطابق العدادات، وP95 أقل من 1,500ms لكل مسار.

## التحسينات المنفذة

- تجميع اتصالات PostgreSQL بقيم افتراضية 4–32 اتصالًا.
- تجديد JWT تلقائيًا واستخدام مسار الخادم الصحيح في الواجهة وأداة الحمل.
- ترقيم API اختياري للقوائم الأساسية، بحجم أقصى 500 سجل للصفحة.
- إزالة عمليات M2M وتحميل الخدمات غير الضرورية من مسار إنشاء/قائمة بطاقات العمل.

## نتيجة 100 ألف

- الزمن الإجمالي: 4,742.80 ثانية (نحو 79 دقيقة).
- أبطأ P95: إنشاء بطاقة العمل عند 817.96ms، ثم المركبة 629.40ms، ثم العميل 623.57ms؛ جميعها دون حد 1,500ms.
- العدادات النهائية: 100,000 عميل و100,000 مركبة و100,000 بطاقة و100,000 في لوحة الملخص.
- سجل التدقيق: 300,001 حدث، وبذلك بقي التدقيق فعالًا طوال الاختبار.
- حجم قاعدة البيانات: 231MB. بعد توقف الحمل استهلك PostgreSQL نحو 151MiB وRedis نحو 5MiB.
- لا إخفاقات HTTP، ولا اختلاف عدادات، ولا أخطاء تحقق.

اجتاز الخادم معيار المرحلة الخاص بحجم 100 ألف سجل. يبقى نقل الشاشات تدريجيًا من الترقيم المحلي إلى طلب صفحات API حتى تحصل واجهة المستخدم على الاستفادة نفسها في الورش ذات البيانات الضخمة.
