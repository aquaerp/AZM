# تقرير اختبار التعافي — 2026-08-21

## النطاق والعزل

- المصدر: نسخة إنتاج أُنشئت للتمرين عند `2026-08-21T17:46:23Z`.
- الهدف: مشروع Docker Compose باسم `azm-staging`، بحجوم مستقلة ومنافذ مرتبطة بـloopback فقط.
- لم تتوقف خدمات الإنتاج ولم تُكتب أي بيانات في قاعدة الإنتاج أثناء التمرين.
- تم التحقق من ملفي قاعدة البيانات والوسائط بواسطة ملف `sha256` قبل بدء الاستعادة.

## نتيجة قابلية النقل

فشلت المحاولة الأولى بأمان قبل استعادة الوسائط لأن التفريغ القديم احتوى أوامر
ملكية للمستخدم `azm_app` غير الموجود في بيئة DR. عولج السبب بجعل النسخ الجديدة
تستخدم `pg_dump --no-owner --no-acl`، ثم أُنشئت نسخة جديدة وأعيد الاختبار.

كما أضيف الخيار `--project-name` إلى أداتي النسخ والاستعادة لمنع استنتاج مشروع
الإنتاج من مسار ملف Compose عند تشغيل تمرين معزول، وأضيف تحقق إلزامي من ارتباط
ملفات قاعدة البيانات والوسائط بملف checksum الممرر قبل أي عملية حذف.

## التنظيف

بعد إثبات النتيجة، حُذفت حجوم Staging التي احتوت بيانات الإنتاج وحُذفت نسخة
التمرين المؤقتة. أُعيد إنشاء Staging بحجوم فارغة، وتم التحقق من وجود `0` ورش
و`0` مستخدمين. بقيت نسخ الإنتاج الأصلية في `/opt/azm-backups` دون تغيير.

## البنود المفتوحة والمتابعة

- ثُبّت `rclone` ووحدتا `azm-backup.service` و`azm-backup.timer` على VPS.
- أُنشئ ملف `backup.env` محمي بصلاحية `600` وضُبط رابط heartbeat.
- عُدلت الوجهة إلى `azm-s3:azm-833565098460-eu-north-1-an/azm`.
- يلزم مفتاح IAM محدود بالحاوية والمسار، ثم إعداد remote `azm-s3` واختبار الرفع و`rclone check`.
- بقي المؤقت معطلاً عمدًا حتى ينجح اختبار الرفع الخارجي، منعًا لتشغيل مهمة معطلة أو تسجيل نجاح وهمي.

نجاح هذا التمرين يثبت مسار الاستعادة المحلي وقابلية نقل النسخة، لكنه لا يغلق
مرحلة التعافي حتى تعمل نسخة خارجية مجدولة ومراقبة فعليًا.
