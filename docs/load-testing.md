# خطة اختبار التحمل

## النطاق والعزل

يعمل الاختبار على قاعدة PostgreSQL مستقلة اسمها `azm_loadtest` ولا يقرأ أو يكتب في قاعدة الورشة اليومية. كل سجل مطلوب في المشغّل ينشئ ثلاثة صفوف مترابطة عبر HTTP API: عميل، مركبة مرتبطة به، وبطاقة عمل مرتبطة بهما. ويتحقق أيضاً من الصفحة الأولى والعدد الكلي لقوائم العملاء والمركبات وبطاقات العمل، ومن لوحة الملخص بعد اكتمال الإدخال.

يعيد المشغّل إنشاء قاعدة الاختبار المعزولة افتراضيًا قبل كل تشغيل، لضمان قياس قابل للتكرار وعدم اصطدام التسجيل التجريبي ببصمات تشغيل سابق. يمكن تمرير `-ReuseDatabase` فقط عند الحاجة إلى قياس تراكمي مقصود؛ ولا يقبل المشغّل أصلًا اسم قاعدة لا يبدأ بـ`azm_loadtest`.

في التشغيلات التي تبلغ 1,000 مجموعة فأكثر، يطبع الاختبار التقدم والمعدل كل 1,000 مجموعة لتسهيل مراقبة التشغيل الطويل واكتشاف التباطؤ المبكر.

يستخدم عميل الحمل pool لاتصالات HTTP بعدد لا يتجاوز قيمة `Workers`، حتى يقيس التطبيق وقاعدة البيانات بدل تكلفة إنشاء اتصال TCP جديد لكل طلب.

يرفع المشغّل حدود DRF مؤقتًا داخل عملية خادم الاختبار فقط حتى يقيس قاعدة البيانات والتطبيق بدل قياس استجابات `429`. تبقى القيم الإنتاجية الافتراضية `60/hour` للمجهول و`1000/hour` للمستخدم، ويمكن ضبطها بمتغيري `AZM_ANON_THROTTLE_RATE` و`AZM_USER_THROTTLE_RATE` دون تعطيل الحماية في الإنتاج.

لا يستهدف المشغّل أي عنوان غير محلي افتراضياً. لا تستخدم خيار `--allow-remote` إلا مع بيئة أداء معزولة ومصرح بها.

## مراحل التنفيذ

| المرحلة | الأمر | الغرض |
| --- | --- | --- |
| تمهيد | `-Records 100 -Workers 8` | فحص المسارات والعلاقات والقياسات قبل التصعيد. |
| تصعيد | `-Records 10000 -Workers 16 -FullScale` | كشف الاختناقات الأولى في الاتصال والفهارس وقاعدة البيانات. |
| حجم مستهدف | `-Records 100000 -Workers 32 -FullScale` | إنشاء 100,000 عميل و100,000 مركبة و100,000 بطاقة عمل (300,000 صف). |

مثال تشغيل المرحلة المستهدفة:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-load-test.ps1 -Records 100000 -Workers 32 -FullScale
```

## معايير القبول

- لا توجد طلبات HTTP فاشلة أو استجابات 5xx.
- P95 لزمن الطلب لا يتجاوز 1,500ms؛ يطبق المشغّل هذا الحد تلقائياً.
- عدد العملاء والمركبات وبطاقات العمل يساوي قيمة `Records` لكل نوع، مع بقاء العلاقات صحيحة.
- يطبق حد P95 على كل مسار API على حدة، لا على المتوسط المجمع فقط، حتى لا تخفي آلاف عمليات الكتابة بطء استجابة قائمة واحدة.
- تؤخذ لقطة من `docker stats` ومن مؤشرات PostgreSQL أثناء مرحلة 100,000 سجل لمراجعة CPU والذاكرة والتخزين والاتصالات.
- عند تجاوز أحد الحدود، يحفظ ملف JSON تحت `tmp/load-test-*.json` المقاييس والأخطاء لتحديد المرحلة والمسار المتأثر.

## نتيجة التشغيل التمهيدي

في البيئة المحلية الحالية، أنشأ التشغيل التمهيدي 100 سجل من كل نوع (300 صف) باستخدام 8 عمال وحقق 307 طلبات ناجحة بلا أخطاء: P50=52.05ms وP95=105.03ms ومعدل 124.16 طلب/ثانية.
